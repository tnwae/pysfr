pysfr
=====
**pysfr** is a C++ program designed to read the information from a Pokemon Yellow save file and display (some of) it to the user in a somewhat friendly format.  I hope to be able to generate save files "from whole cloth" someday.

To compile the PYSFR, simply issue the `make` command in a command shell after cloning the source distribution:

    UNIX> git clone https://github.com/tnwae/pysfr
    UNIX> cd pysfr
    UNIX> make

PYSFR is a command line application.  You use it by opening a terminal window and pointing the executable at a raw save file:

    UNIX> ./pysfr some-save-file.sav

PYSFR comes with two utility programs, `game-dumper` and `dumper`, which dump the information from a game ROM and from the save file respectively, adjusting (most) characters to the ASCII character set.  To use them, type `make game-dumper` and `make dumper` at the command line, then call the programs:

    UNIX> ./dumper some-save-file.sav
    UNIX> ./game-dumper some-game-rom.sgb

The game dumper is idiosyncratic to the first-generation games, which use a 1024 KiB ROM.  You'll probably find the disassembly of the game more useful.

PYSFR should run on any little-endian processor supported by a mainstream compiler that supports C++11.  I have tested it personally only on x64 Linux.  I neither know nor care how it works on non-Linux platforms, particularly macOS.  I despise Apple and refuse to support them, directly or by proxy, by purchasing a Macintosh.

Shortcomings
============
It doesn't support the Japanese version, and it probably never will.  It also doesn't support European versions (e.g. in French, German, Italian) but since the character set is reasonably similar, it shouldn't be hard to figure out the differences.

Some functionality probably needs to be broken out into a library.

How to help
===========
I'm looking for save files, lots and lots of save files.  I'm hoping to catalog a complete list of all event flags and structures in the save file.  Conservatively, I'd say we're looking at somewhere in the neighborhood of 5,000 items counting Pokedex flags, battled trainers, completed scripts (e.g. sidequests), Hall of Fame data, and PC storage.  My goal is to be able to represent these save files in some intermediary format (e.g. XML) so that save files can be generated _de novo_ for any conceivable game situation.

In particular, I want the raw battery-backed save (exactly 32768 bytes) generated by your emulator.  These are the files PYSFR can read.  I'll accept save files from any Western version of Red, Blue, or Yellow; if you include a file from a non-US version, please indicate where it comes from (e.g., France, Germany, Latin America) so I can make modifications to the character set and documentation as needed.

To submit your file, please create a subdirectory off of `test_files/` with your github username.  Include the `.sav` file (the battery-backed save) and, if you wish, a brief description in Markdown, reStructuredText, Textile, or plain text.  Then submit a pull request so I can fold your file(s) into the main repository.  If you'd like to contribute multiple files, please provide descriptions with each.

Also, if you'd like to hack on this code and submit a pull request, knock yourself out.
